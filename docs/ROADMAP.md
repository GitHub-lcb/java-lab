# Content Roadmap

这个路线图只安排课程内容和教学能力。服务器公网发布暂缓，真实实验继续使用本机或受保护内网环境。

## 当前优先级：JVM 诊断能力

`v2-jvm-foundation` 已完成六课模拟、白名单 JDK 实机探针、原理精讲和专题学习中心。下一步依次完成：

1. 已完成：Serial、Parallel、G1 的目标、工作分布和选择边界
2. 下一步：GC 日志分析，包括统一日志字段、时间线、停顿原因和晋升压力
3. OOM/泄漏诊断：堆、Metaspace、直接内存和线程资源的证据链
4. JIT 编译与逃逸分析：分层编译、内联、去优化和标量替换

## 当前版本

- 13 课 Redis 核心路径及确定性原理模拟
- 每课的真实 Redis 命令实验、模型边界和官方资料
- 缓存读写、数据类型、TTL、原子扣减四课的原理精讲
- 真实步骤按顺序和 RESP 返回值验证；命令执行成功不等于步骤通过
- 阶段测验、错题复习、对照任务和专题总评
- JVM 七课原理精讲、四组阶段测验、模块化错题本和专题总评
- JVM 七个课程入口对应固定白名单实机探针，覆盖 javap、ClassLoader、内存池、分配字节、弱引用与 GC MXBean
- 收集器对比课程使用抽象工作单位解释 Serial、Parallel 与 G1，不把模拟结果表示成毫秒或性能基准

## Redis backlog：后续迭代

以下内容已转入 `BACKLOG.md`，不阻塞 JVM 建设。后续按以下顺序补全：

1. 缓存穿透：空值标记、布隆过滤器误判与数据同步边界
2. 缓存击穿：请求合并、互斥重建、逻辑过期与尾延迟
3. 缓存雪崩：TTL 分散、限流、降级和重试放大
4. 缓存一致性：更新后删除、删除失败补偿、CDC 与旧读窗口
5. 事务与 Lua：WATCH 冲突、MULTI/EXEC 错误语义、脚本阻塞边界
6. 分布式锁：token + Lua、租约续期、进程暂停和 fencing token
7. 持久化：RDB/AOF 配置读取、可控重启、恢复结果与 RPO
8. 高可用：复制位点、Sentinel 切换、Cluster slot 与客户端重定向
9. 运维诊断与综合演练：大 Key、热 Key、慢命令、容量和故障组合

完成标准：每课都必须具备“现象、因果链、错误反例、真实返回值验证、生产边界、业务迁移题”，不能只增加说明文字或命令列表。

## 第二阶段：Java 客户端与 Spring Boot

- Lettuce/Jedis 连接模型、连接池与线程安全边界
- RedisTemplate 序列化及 Java/Jackson 类型兼容问题
- Spring Cache 命中、Key 生成、空值、TTL 和条件缓存
- 超时、重试、熔断与请求放大
- Cache-Aside 业务代码、事务提交后失效和可靠补偿
- Lua 脚本版本管理、SHA 缓存与降级

真实 Java 代码应在隔离的示例服务中运行，输出请求日志、Redis 命令、耗时和最终数据。教学结果不得伪造为生产性能数据。

## 第三阶段：受控故障实验

- 单实例 RDB/AOF 恢复
- 主从复制延迟与未复制写入窗口
- Sentinel 故障转移
- Cluster slot、MOVED/ASK 和跨 slot 限制
- 客户端连接恢复、拓扑刷新和重试

这些实验使用独立 Docker Compose 拓扑和可丢弃数据，不能操作用户已有 Redis 或生产实例。每次实验要有启动、健康检查、故障注入、结果验证和完整清理流程。

## 暂不做

- 不把当前无认证 Java 网关直接暴露公网
- 不提供任意 EVAL、CONFIG、KEYS、MONITOR 或清库能力
- 不把单机 PING 当作 Sentinel/Cluster 高可用验证
- 不用静态动画代替持久化恢复或故障转移的真实证据
- 不引入图库图片；需要位图时仅使用生图工具生成原创资产
